4. LIMITES DO FREE TIER CLOUDFLARE (importante para o LadiesGo)
--------------------------------------------------------------------------------

O AGENTS.md do projeto já alerta sobre esses limites. Resumo:

  Serviço   | Grátis                    | Limite crítico
  ----------|---------------------------|-------------------------------------------
  Workers   | 100.000 requests/dia      | Por conta; erro 1027/429 se estourar
  D1        | 25 bancos, 5 GB storage   | 100.000 ESCRITAS/dia; erro 7500 se estourar
  KV        | 10 GB storage             | 100.000 leituras/dia
  R2        | 10 GB storage             | 1M operações Classe A/mês, zero egress
  Pages     | Banda ilimitada           | 500 builds/mês

Regras do AGENTS.md (não repetir erros de 2026-10-17):
  • NUNCA rodar wrangler logout — revoga o token
  • NUNCA rodar testes de carga (k6, firetest, ws-storm) contra produção
  • NUNCA reimportar o D1 inteiro repetidamente; usar migrations incrementais
  • Preferir WebSocket a polling (mensagens WS não contam como requests do Worker)
  • Trocar conta com cloudflare\use-account.ps1 old / new

5. RECOMENDAÇÕES PRÁTICAS PARA ESCALAR O LADIESGO COM POUCO RECURSO
--------------------------------------------------------------------------------

a) Monitore as escritas do D1 — é o maior gargalo hoje. Não reimportar o banco
   inteiro. Usar wrangler d1 migrations apply (incremental).

b) Use WebSocket primeiro, polling como fallback — já é o padrão do webapp,
   manter assim para economizar requests do Worker.

c) Considere Cloudflare R2 para fotos de perfil das motoristas/passageiras
   (10 GB grátis, zero taxa de saída de dados).

d) Considere Cloudflare KV para cache de sessões e dados pouco mutáveis
   (100.000 leituras/dia grátis).

d) Mantenha o frontend em Cloudflare Pages — banda ilimitada, 500 builds/mês.

e) Não rode testes de carga contra produção. Use staging ou a 2ª conta.

f) Ao trocar de conta Cloudflare, copiar default.toml antes e usar
   use-account.ps1, nunca wrangler logout.
